## Introduction

Lesson 1.1 explained *why* Delta Platform exists. ### Reading the Diagram

A few things worth calling out explicitly:

- **KX Control is the control plane, not the data plane.** It doesn't carry your data — it's the single UI you use to configure, deploy, start, stop, and monitor every process in the diagram below it. Everything you'll click through in Module 2 is this layer.
- **Everything lives inside a Package.** Every process, schema, analytic, and workflow you create is bundled into a versioned, Git-trackable package — that's what Module 3 covers. The dashed box in the diagram represents this: nothing is a loose file sitting on a server, it's an entity inside a package that KX Control knows about.
- **Processes are built from Process Templates.** The Tickerplant, RDB, HDB, FileWatcher, and Gateway boxes in the diagram aren't bespoke scripts — each is a **Process Instance**, created from a reusable **Process Template**, and (per good practice) run as a **Task**, optionally sequenced by a **Workflow**. Module 4 is entirely about this template → instance → task → workflow chain.
- **There are two ways data gets in.** The top lane is the classic kdb+ "tick" pattern — a Tickerplant publishing real-time events that land in an in-memory RDB, which rolls down to the on-disk HDB at end of day. The bottom lane is a FileWatcher watching for files (CSVs, JSON exports, whatever a vendor drops) and loading them directly. This course builds the FileWatcher path by hand (Module 5), since it's the more common first task for someone new to a project: most new joiners get asked to wire up a new data feed, not to rebuild the core tickerplant.
- **Messaging Server is the glue, not a destination.** It's what lets one process (like a Tickerplant) publish and another (like an RDB) subscribe, without either one hard-coding the other's host and port. Module 6 covers this.
- **The Gateway is the only thing a client talks to.** A dashboard or user never queries the RDB or HDB directly — they query the Gateway, which knows how to route the request to whichever database (or both) holds the relevant data, and hands back a single combined answer. Module 8 covers this, and it's the payoff lesson: by then you'll have built every piece that the Gateway sits in front of.

### What This Means for Outcome #1

If you look at the diagram again, notice that the path from "a file lands on disk" to "a client gets a query result back" touches almost every box in it. That's deliberate — it's the same path outcome #1 asks you to be able to build by the end of this course: a working data ingest and a working data query, on Delta Platform, from first principles.
