# Lesson 1.3 - Learning Outcomes and Course Roadmap

_Module 1: Introduction to Delta Platform · ~5 min_

## Introduction

This lesson states what you should be able to do by the end of this course, and shows how the remaining modules get you there.

## Key Concepts

### The 3 Learning Outcomes

By the end of this course, you should be able to:

1. **Build a working data ingest and data query on Delta Platform** — take a real file of data, get it into the system, and query it back out, using the platform's own tools rather than writing a tick system from scratch.
2. **Explain how Delta Platform differs from native kdb+ development** — recognize what the platform gives you (Control, packaging, templates, messaging, the gateway) that you'd otherwise have to build yourself, and why a client project built on it looks different from a hand-rolled kdb+ codebase.
3. **Handle basic development tasks on Delta Platform** — the everyday things a new joiner gets asked to do: create and configure a process, write and wire up an analytic, package your work, and query data through the gateway.

### How the Modules Map to the Outcomes

| Module | What it covers | Outcome(s) it builds toward |
|---|---|---|
| 1 — Introduction to Delta Platform | Why the platform exists; its architecture; this roadmap | 2 |
| 2 — Delta Control | Navigating KX Control: the UI, navigation tree, viewers, editors | 2, 3 |
| 3 — Packaging and Deployment | Creating, exporting, importing, and naming packages | 2, 3 |
| 4 — Process Templates, Instances and Workflow Assembly | Building the TP/RDB/HDB instances, tasks, and a workflow to run them together | 1, 2, 3 |
| 5 — Building the FileWatcher Data Loader | Writing an analytic that loads a real CSV file into the system | 1, 3 |
| 6 — Pub/Sub and Data Publishing | Wiring processes together over the messaging server | 1, 2 |
| 7 — End-of-Day Processing and Persistence | *(planned, not yet written — see the [section README](../07-end-of-day/README.md))* | 1 |
| 8 — Querying via the Gateway | Connections, routing, aggregation, and a full worked query across RDB + HDB | 1, 2, 3 |

Read down the "What it covers" column and you'll notice it's the same left-to-right path as the architecture diagram in Lesson 1.2: set up the processes, load data in, connect them together, and query it back out. That's not a coincidence — outcome #1 *is* that path, built one module at a time.

### What "Done" Looks Like

By Module 8, you'll have a package containing your own Tickerplant/RDB/HDB instances, a FileWatcher that loads a sample file, a workflow that starts them in the right order, and a gateway query that pulls combined results from RDB and HDB — built and configured by you, inside KX Control, from the ground up. That's outcome #1, and outcomes #2 and #3 are what you'll have picked up along the way to get there.
