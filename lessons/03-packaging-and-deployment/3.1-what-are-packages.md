# Lesson 3.1 - What are Packages in Delta Control?

_Module 3: Packaging and Deployment · ~TBD min_

## Introduction

This lesson defines what packages are in Delta Control and how to use them.

## Key Concepts

Every object you build in KX Delta Platform — a process, a schema, an analytic, an alert, a connection, and so on — is called an **entity**. As you build out a system, you will end up with dozens or hundreds of these entities. KX Control gives you a structured way to group entities together, move them between environments (dev → test → prod), and keep them under version control using Git. These are called **packages.**

This module covers three related topics:

1. How **packaging** works — how entities are grouped, exported and imported.
2. How packages connect to **Git** for version control and collaboration.
3. **Coding practices and naming conventions** to follow when you start creating your own entities.

By the end of this module, you should understand what a package is, how to move one between environments, and how to name and structure the things you build so they stay consistent with the rest of the system.

### What is a Package?

A **package** is a logical container that groups related entities together (processes, schemas, analytics, alerts, etc.) so that they can be managed, versioned and moved as a single unit.

Under the hood, a package is simply an **XML representation** of the entities it contains, held in a directory on the KX Control server. Nothing about a package changes what an entity *is* — it is purely an organizational and deployment mechanism.

A few important things to understand:

- **Packages are not automatically in sync with the live system.** Changes made in the KX Control UI are not written to the package's XML files until you explicitly *export* the package. Likewise, changes made to the XML files on disk (for example, by another developer) are not reflected in your running environment until you *import* the package.
- **Dependencies between entities are handled for you.** When you export or import a package, KX Control works out the relationships between entities (e.g. a process that depends on a schema) so they stay consistent.
- **Every entity belongs to a package — or none.** Entities that haven't been assigned to a package yet are shown in the Navigation panel under **Unpackaged Entities**, so they're easy to find and tidy up. This is where all new dashboards are initially placed when they are created.

Think of a package as similar to a project or module folder in traditional software development — a way to bundle related code so it can be built, versioned and shipped as a unit.
