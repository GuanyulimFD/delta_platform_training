# Lesson 6.8 - Creating the Publishing Analytics

_Module 6: Pub/Sub and Data Publishing. ~TBD min_

## Introduction

This lesson creates the two file watcher analytics that read the new CSVs and publish them to the tickerplant.

## Key Concepts

These analytics follow the same shape as `fileWatcher.read_sampleOrders` from Lesson 5.5. They take the same two parameters and load the CSV the same way. The difference is what happens next: instead of saving the table to disk, they publish it with `.dm.pub`, the messaging publish function from Lesson 6.3.

### Creating the orders analytic

Create a new analytic called `fileWatcher.pub_sampleOrders` in the `delta_training_1_0_0` package. As in Lesson 5.5, set up the Parameters tab **before** the Contents. It takes two parameters, `dir` and `file`, both of type Symbol.

```q
{[dir;file]
  .log.out[.z.h;"Processing file";file];

  // Build the full path to the file
  path:.Q.dd[dir;file];

  // Load the CSV.
  // "PSJF" describes the column types in order: Timestamp, Symbol, Long, Float
  // enlist "," tells 0: to treat the first line as column headers
  orders:("PSJF"; enlist ",") 0: path;
  .log.out[.z.h;"Loaded row count:";count orders];

  // Publish to the tickerplant on this process's publishChannel
  .dm.pub[`sampleOrders;orders];

  .log.out[.z.h;"File publish complete";file];
 }
```

### Creating the reference data analytic

Create a second analytic called `fileWatcher.pub_sampleReferenceData`, with the same two parameters:

```q
{[dir;file]
  .log.out[.z.h;"Processing file";file];

  path:.Q.dd[dir;file];

  // "PSSS": Timestamp, Symbol, Symbol, Symbol (time, sym, industry, region)
  refData:("PSSS"; enlist ",") 0: path;
  .log.out[.z.h;"Loaded row count:";count refData];

  .dm.pub[`sampleReferenceData;refData];

  .log.out[.z.h;"File publish complete";file];
 }
```

A few things worth calling out:

- The first argument to `.dm.pub` is the **table name**. It must match a schema the TP and RDB know about, which is why the schemas were bound through `refdata_schemas` in Lesson 6.6.
- The column types passed to `0:` must match the schema. Both files start with a Timestamp (`P`) `time` column, as the TP requires.
- There's no date extraction and no `set`. Writing to the HDB is now the RDB's job at end-of-day (Module 7).

### Adding the analytics to the file watcher

The file watcher only accepts analytic groups, and it already has `fileWatcher_analytics` from Lesson 5.5. Open `fileWatcher_analytics` and, in the Analytic Group Contents tab, move `fileWatcher.pub_sampleOrders` and `fileWatcher.pub_sampleReferenceData` into the Selected Analytics section. Click Save.

Because the group is already bound to `sampleOrder_fileWatcher`, there's nothing more to add on the instance itself. Restart the file watcher so it loads the updated group.

### What the RDB does with the data

On the receiving side, the RDB's `realTimeMsgFunct` (`dxUpdInsertPub`, Lesson 4.3) inserts each published update into the matching table. Neither course table has key columns, so the default update function is all we need. No custom update function is required.
