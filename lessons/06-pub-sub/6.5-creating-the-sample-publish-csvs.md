# Lesson 6.5 - Creating the Sample Publish CSVs

_Module 6: Pub/Sub and Data Publishing. ~5 min_

## Introduction

This lesson creates two sample CSVs that will be published to the tickerplant, instead of being saved straight to disk.

## Key Concepts

In Module 5 the file watcher's loader analytic read `sampleOrders_20260101.csv` and saved it directly into the HDB directory. That is a common pattern for batch data, but the data never passes through the tickerplant (TP) or the real-time database (RDB), so it can't be queried intraday and isn't part of the end-of-day (EOD) process covered in Module 7.

Over Lessons 6.5–6.9 we'll build a second path for the same kind of data: the file watcher reads a file and **publishes** it to `refdata_tp_reference_a`, which logs it and passes it on to `refdata_rdb_reference_a`. We'll publish two tables:

- `sampleOrders`: the same orders table as Module 5
- `sampleReferenceData`: a small reference table describing each symbol

As in Lesson 5.2, create both files on the server in a location that is **not** being watched by the file watcher. They'll be copied into the watched directory in Lesson 6.9.

### Sample orders file

Create a file named `sampleOrdersPub_20260102.csv` with the contents below. These are the same five orders as Lesson 5.2, moved to a more recent date:

```
time,sym,qty,price
2026-01-02T09:30:00.000,AAPL,100,182.35
2026-01-02T09:31:12.500,MSFT,50,412.10
2026-01-02T09:32:45.250,GOOG,25,168.90
2026-01-02T09:34:03.100,AAPL,75,182.50
2026-01-02T09:36:22.750,AMZN,10,201.75
```

The filename still follows the `<tableName>_<date>.csv` convention from Lesson 5.2, with `Pub` added to the table name. This matters. The file watcher from Module 5 already has a rule matching `sampleOrders_*.csv`, which batch-loads the file to disk. A file named `sampleOrders_20260102.csv` would be picked up by that rule as well. The distinct name lets us give the published file its own rule in Lesson 6.7.

### Sample reference data file

Create a file named `sampleReferenceData_20260102.csv` with the contents below:

```
time,sym,industry,region
2026-01-02T09:30:00.000,AAPL,technology,california
2026-01-02T09:30:00.000,TSLA,automotive,texas
2026-01-02T09:30:00.000,MSFT,computers,new_york
2026-01-02T09:30:00.000,GOOG,websearch,florida
```

Note that `time` is the **first column** in both files. Every table published to the TP must have `time` as its first column, including reference data that isn't really time-series. Here it simply records when the reference data was produced.

Notice also that the orders file contains an AMZN order but the reference file has no AMZN row, and the reference file has a TSLA row with no TSLA orders. This is deliberate and typical of real data. We'll come back to it when validating the HDB in Module 7.
