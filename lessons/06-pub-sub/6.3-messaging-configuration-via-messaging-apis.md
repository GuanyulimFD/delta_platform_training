# Lesson 6.3 - Messaging Configuration via Messaging APIs

KX Platform also provides a set of apis for its messaging/pub/sub framework. These functions are all defined as part of the dm namespace, which stands for Delta Messaging.

This lesson will aim to go over the basic functions and provide an end to end example of its usage.

## 1. API Reference

### A. Subscriber Registration Functions

These functions are used by a subscriber process to register its interest in receiving table updates from messaging servers.

| Function | Description / Mode |
|---|---|
| `.dm.regsub` | Standard segmented subscription function for registering a subscriber against a messaging topic. |
| `.dm.regsubc` | Segmented subscription function for subscribers with explicit channel handling. |

### B. Source/Publisher Registration Functions

These functions are used by publishers or data sources to register themselves with the messaging framework so that subscribers can discover and stream data from them.

| Function | Description / Mode |
|---|---|
| `.dm.regsrc` | Registers a data source/publisher with source filtering capabilities. |
| `.dm.regsrcc` | Registers a data source with both source filtering and explicit channel routing. |

### C. Unsubscription Functions

Unsubscription functions clean up and remove registered streams from messaging servers.

| Function | Description / Mode |
|---|---|
| `.dm.unsub` | Standard unsubscription function for a subscriber to stop receiving a specific table stream/topic. |

### D. Publish Functions

Publish functions enable real-time and historical publishers to broadcast table updates out to matching subscribers.

| Function | Description / Usage |
|---|---|
| `.dm.pub` | Standard publish function that pushes table data to registered subscribers, evaluating individual subscription/column filters. |
| `.dm.pubc` | Publishes streaming table updates constrained to a specific channel tag (useful for routing/hot-hot configurations). |
| `.dm.pubnoreply` | Publishes table updates asynchronously without waiting for or expecting any acknowledgment/reply from targets. |
| `.dm.pubdata` | Handles lower-level raw data packaging and broadcasting for stream network packets. |

### E. Callback Functions

Callback functions manage how incoming table payloads are processed locally upon receipt.

| Function | Description / Parameters |
|---|---|
| `.dm.addCallback` | Binds a user-defined function to a specific table name ([table; function]). |
| `.dm.applyCallbacks` | Evaluates and applies the registered callback functions when updates arrive ([table; data]). |
