# Lesson 6.5 - Publishing Sample Data to the TP

_Module 6: Pub/Sub and Data Publishing. ~25 min_

## Introduction

This lesson publishes two sample files through the tickerplant to the RDB, reusing the file watcher built in Module 5.

## Key Concepts

In Module 5 the file watcher's analytic saved `sampleOrders` straight to the HDB directory. In this lesson, the file watcher publishes the data on `refdata_channel` instead. `refdata_tp_reference_a` subscribes to that channel and passes the data on to `refdata_rdb_reference_a` on `refdata_tp` (the channels set in Lesson 4.3). The data can then be queried in the RDB during the day, and it's saved to the HDB at end-of-day (Module 7).

Two tables are published:

- `sampleOrders`: the orders table from Lesson 5.3
- `sampleReferenceData`: a new reference data table

### Sample reference data

Reference data describes the instruments themselves rather than events such as orders or trades. It changes rarely and is joined onto event data by a shared key, here `sym`. `sampleReferenceData` gives each symbol's industry and region. Its four rows are the same values used in the `referenceData` example in Lesson 8.5, so the data loaded here can be used in Module 8.

### Sample files

Create both files as in Lesson 5.2, in a directory the file watcher does not watch.

`sampleOrdersPub_20260102.csv` has the same five orders as Lesson 5.2, dated 2026-01-02:

```
time,sym,qty,price
2026-01-02T09:30:00.000,AAPL,100,182.35
2026-01-02T09:31:12.500,MSFT,50,412.10
2026-01-02T09:32:45.250,GOOG,25,168.90
2026-01-02T09:34:03.100,AAPL,75,182.50
2026-01-02T09:36:22.750,AMZN,10,201.75
```

`sampleReferenceData_20260102.csv`:

```
time,sym,industry,region
2026-01-02T09:30:00.000,AAPL,technology,california
2026-01-02T09:30:00.000,TSLA,automotive,texas
2026-01-02T09:30:00.000,MSFT,computers,new_york
2026-01-02T09:30:00.000,GOOG,websearch,florida
```

- The orders file is named `sampleOrdersPub_…` because Module 5's `sampleOrders_*.csv` rule would otherwise batch-load it to disk as well.
- Every table published to the TP must have `time` as its first column, so the reference file has one too.
- There is no AMZN reference row and no TSLA order. Lesson 7.4 uses this when checking the HDB.

### Schemas and the schema group

A schema group bundles schemas so they can be assigned to processes together. The TP and RDB both need `sampleOrders` and `sampleReferenceData`, so both are bound through one group, `refdata_schemas` (KX guide: https://code.kx.com/platform/latest/stream/dw_schema.html).

1. **Create the group.** Right-click the `delta_training_1_0_0` package and select **New > Schema Group**. Enter the name `refdata_schemas`, select the package `delta_training_1_0_0`, click **Add**, then **Save**.
2. **Create the reference schema in the group.** Right-click `refdata_schemas` and select **New > Schema**. Name it `sampleReferenceData` in `delta_training_1_0_0`, then add these columns on the Columns tab as in Lesson 5.3, and save:

   | Column | Type | Key Column |
   |---|---|---|
   | time | Timestamp | false |
   | sym | Symbol | false |
   | industry | Symbol | false |
   | region | Symbol | false |

3. **Add the orders schema to the group.** Open `sampleOrders` (Lesson 5.3), go to the **Groups** tab, move `refdata_schemas` to the selected groups and save. On `sampleReferenceData`'s Groups tab, confirm it is already in `refdata_schemas`.
4. **Bind the group to the TP and RDB.** On the Schemas tab (Lesson 4.4) of `refdata_tp_reference_a`, move `refdata_schemas` from **Available Schema Groups** to **Selected Schema Groups** and save. Repeat for `refdata_rdb_reference_a`.

Schemas are loaded when a process starts, so restart the TP and RDB after binding the group.

### File watcher rules

Add two rows to `sampleOrder_fileWatcherConfig` (Lesson 5.4):

| fileregex | directory | analytic | alertTime |
|---|---|---|---|
| `sampleOrdersPub_*.csv` | ENV=DELTADATA_HOME=/fileStore | `fileWatcher.pub_sampleOrders` | 00:00:00.000 |
| `sampleReferenceData_*.csv` | ENV=DELTADATA_HOME=/fileStore | `fileWatcher.pub_sampleReferenceData` | 00:00:00.000 |

Then set these Instance Params on `sampleOrder_fileWatcher`, save, and restart it (Lesson 6.2):

| Parameter | Value for Course | Description |
|---|---|---|
| messagingServer | DS_MESSAGING_SERVER:DS | Messaging server config (Lesson 6.1) |
| publishChannel | refdata_channel | Must match the TP's subscriptionChannel |

### Publishing analytics

Create `fileWatcher.pub_sampleOrders` in `delta_training_1_0_0`, with the same `dir` and `file` Symbol parameters as Lesson 5.5. It loads the CSV as 5.5 does, then publishes it with `.dm.pub` (Lesson 6.3) instead of saving it:

```q
{[dir;file]
  .log.out[.z.h;"Processing file";file];
  orders:("PSJF"; enlist ",") 0: .Q.dd[dir;file];
  .dm.pub[`sampleOrders;orders];
  .log.out[.z.h;"Published rows:";count orders];
 }
```

Create `fileWatcher.pub_sampleReferenceData` the same way, with two changes: the types are `"PSSS"` (time, sym, industry, region), and it publishes as `` `sampleReferenceData ``.

Add both analytics to `fileWatcher_analytics` (Lesson 5.5) and restart the file watcher. The RDB inserts what it receives using its default `realTimeMsgFunct`, `dxUpdInsertPub` (Lesson 4.3). Neither table has key columns, so no custom update function is needed.

### Worked example

1. Run the `Refdata_launch_PROCS_A` workflow (Lesson 4.7), then run `sampleOrder_fileWatcher` and connect to it (Lesson 5.6).
2. Copy both CSVs into `ENV=DELTADATA_HOME=/fileStore`. The file watcher log shows "Processing file" and "Published rows:" for each file.
3. Connect to `refdata_rdb_reference_a` and check the data:

   ```q
   count sampleOrders            / 5
   count sampleReferenceData     / 4
   ```

   Only the published orders are in the RDB. Module 5's batch load went straight to the HDB.

If nothing arrives, check in this order:
- the `fileregex` matches the filename
- both analytics are in `fileWatcher_analytics` (an `analyticnotdefined` error means they aren't)
- the channels match
- `refdata_schemas` is bound to the TP and RDB, and both were restarted
