# Lesson 6.1 - Overview of Messaging Server

Messaging is a publish-subscribe framework bundled with KX Stream. It runs in a server-client model with a messaging server process acting as the discovery service for processes that consume or publish data.

The messaging server for a process can be configured in the **messagingServer** parameter in the process instance params. This contains a **configparam** consisting of instance names. The messaging server instance will default to **ds_ms_a** and **ds_ms_b**, which are deployed as part of the default delta platform packages (part of DeltaStream package).

![Instance Params tab for ds_tp_ops_a showing the messagingServer parameter (Config, value DS_MESSAGING_SERVER:DS) with a dropdown open listing DS_MESSAGING_SERVER:DEFAULT, DS_MESSAGING_SERVER:DS, DS_OPS_CONNECTIONS, and other config overrides, alongside publishChannel, subscriptionChannel, subscriptionTableList, logDirectory, dsLsInstance, timeOffset, pubFreq, eodTime, initialStateFunct, logRecoveryFunct, and includeColumns parameters](images/6.1-messaging-server-status.png)

Subscribers can listen to a channel and a table or set of tables (leave blank to subscribe to all tables). These can be defined in the process instance template or inputs in the messaging server.
Subscribers can also filter their subscription on specific column values (only symbols are supported), known as sharding. This can only be done via the messaging functions rather than subscriptions controlled through the process instance parameters.
