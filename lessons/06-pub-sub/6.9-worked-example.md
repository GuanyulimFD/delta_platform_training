# Lesson 6.9 - Worked Example: Publishing to the RDB

_Module 6: Pub/Sub and Data Publishing. ~TBD min_

## Introduction

This lesson goes through the whole process of publishing the two sample CSVs through the tickerplant and confirming the data reaches the RDB.

## Key Concepts

1. Start the core processes. Search for the `Refdata_launch_PROCS_A` workflow in the Process Library Status, then right click and select 'Run'. The HDB and TP start first, then the RDB.
2. Run the file watcher: right click `sampleOrder_fileWatcher` (or its task) in the Process Library Status and select 'Run'.
3. To see the logging as it happens, right click the file watcher again and select 'Connect'. This opens an Analyst session, as in Lesson 5.6.
4. Copy `sampleOrdersPub_20260102.csv` and `sampleReferenceData_20260102.csv` (from Lesson 6.5) into the directory the file watcher is watching (`DELTADATA_HOME/fileStore`, as in Lesson 5.6).
5. In the file watcher's log you should see, for each file, the "Processing file", "Loaded row count:" and "File publish complete" lines from the analytics in Lesson 6.8.
6. Now connect to `refdata_rdb_reference_a` (right click → 'Connect') and check that the data has arrived:

   ```q
   count sampleOrders            / 5
   count sampleReferenceData     / 4
   select from sampleReferenceData
   ```

   The RDB only holds the five published orders. The rows batch-loaded in Module 5 went straight to the HDB and never passed through the RDB.

> **Note:** the Module 6 outline also asks learners to check the subscriptions in the messaging server. The function or viewer for doing this isn't covered in the course yet.

### Troubleshooting

- **The file watcher logs the file but nothing else happens:** the filename doesn't match a `fileregex` in `sampleOrder_fileWatcherConfig` (Lesson 6.7).
- **`analyticnotdefined` error:** the publish analytics aren't in `fileWatcher_analytics`, or the file watcher wasn't restarted after the group changed (Lesson 6.8).
- **The analytic completes but the RDB is empty:** check the channels. The file watcher's `publishChannel` must be `refdata_channel` (the TP's `subscriptionChannel`), and the RDB's `subscriptionChannel` must be `refdata_tp` (the TP's `publishChannel`).
- **Errors about an unknown table:** `refdata_schemas` isn't bound to the TP or RDB, or they weren't restarted after binding it (Lesson 6.6).
