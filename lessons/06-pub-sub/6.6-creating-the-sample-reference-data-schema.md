# Lesson 6.6 - Creating the Sample Reference Data Schema

_Module 6: Pub/Sub and Data Publishing. ~TBD min_

## Introduction

This lesson creates a schema for the sample reference data, and binds both course schemas to the tickerplant and RDB through a schema group.

## Key Concepts

The TP and RDB can only handle tables they know the structure of. In Lesson 5.3 we created the `sampleOrders` schema, but it hasn't been given to any process yet. The file watcher's analytic loaded the CSV and wrote it to disk itself. Now that the data is being published, both the TP and the RDB need the schemas.

### Creating the reference data schema

Following the same method as Lesson 5.3, go to File in the top left corner, select New -> Schema, and create a schema called `sampleReferenceData` in the `delta_training_1_0_0` package.

Add the following columns to match the CSV created in Lesson 6.5:

| Column | Type | Key Column |
|---|---|---|
| time | Timestamp | false |
| sym | Symbol | false |
| industry | Symbol | false |
| region | Symbol | false |

`time` must be the first column, because the TP requires it on every published table. `sym` is also important: the end-of-day process in Module 7 saves each table to the HDB partitioned on its `sym` column.

### Creating a schema group

Just as analytics are added to processes through analytic groups (Lesson 5.5), it's good practice to bind schemas through a **schema group**, so that every process that needs the course's tables gets the same set.

- Create a new Schema Group called `refdata_schemas` and add it to the `delta_training_1_0_0` package.
- Add the `sampleOrders` and `sampleReferenceData` schemas to the group.
- Click Save.

### Binding the schema group to the TP and RDB

The Schemas tab (Lesson 4.4) binds schemas and schema groups to a process, so the process loads those table definitions on startup.

1. Open `refdata_tp_reference_a` and go to the Schemas tab.
2. Find `refdata_schemas` under the available Schema Groups and move it to the selected Schema Groups.
3. Click Save.
4. Repeat for `refdata_rdb_reference_a`.

If you don't see the schema group, close the instance and open it again. Like the analytic groups in Lesson 5.5, instances don't automatically refresh when new entities are created.

Process configuration changes are only picked up when a process starts, so restart the TP and RDB (for example, via the `Refdata_launch_PROCS_A` workflow) after saving.
