## Introduction

This lesson performs the same start, stop, status, and log operations as Lesson 4.5, but entirely from the terminal using the `kxp` CLI. The kxp command line tool is KX Platform's dedicated command-line tool, documented at `cli.html`.

## Key Concepts

### The `kxp` CLI

The `kxp` binary lives under `${DELTABIN_HOME}/bin`. It can be run directly from that directory, or from any location after sourcing `delta.profile`:

```bash
cd ${DELTABIN_HOME}
source delta.profile
```

Once sourced, `kxp` is available from any working directory. All commands follow the structure:

```
kxp <resource> <operation> <arguments>
```

Pass `-h` at any level (`kxp -h`, `kxp instance -h`, `kxp instance start -h`) to see the help page for that resource or operation.

```
kx-training@kxdbdev:~/kxinstall/delta-bin/bin$ ./kxp -h

  Kx Platform management tool.

  Usage:
      kxp
      kxp -h
      kxp <resource> -h
      kxp <resource> <operation> -h
      kxp [options] <resource> <operation> [<args>]

  Options:
      -h, --help                 Show help message
      -v, --version               Show version
      --cli-debug                 Enable debug logging
      --cli-format=<text|json>    Request output as text or JSON

  Resources:
      control
      daemon
      instance
      package
      service
      session
      user
      usergroup
      workflow
```

### Instance operations

The `instance` resource manages individual process instances:

| Command | What it does |
|---|---|
| `kxp instance list` | List all defined instances in the platform |
| `kxp instance status` | Show running status (host, port, PID) for all instances |
| `kxp instance status <name>` | Show running status for a single named instance |
| `kxp instance describe <name>` | Return configuration details for a named instance |
| `kxp instance start <name>` | Start a named instance |
| `kxp instance stop <name>` | Stop a named instance |

For example, to start and then stop `refdata_tp_reference_a`:

```bash
kxp instance start refdata_tp_reference_a
kxp instance status refdata_tp_reference_a
kxp instance stop refdata_tp_reference_a
```

### Where log files live on disk

Log files are configurable but default to the platform's data directory.

On a standard Linux installation the relevant directory is:

```
~/kxinstall/delta-data/DeltaControlData/logdir/
```

This directory contains:

| File | Contents |
|---|---|
| `DeltaControl.log` | KX Control platform log |
| `DeltaControlDaemon.log` | Delta daemon log |
| `<instance-name>.<date>.log` | Per-process instance log (name and rolling pattern set by `DC_LOGGING`) |

To follow a process log in real time:

```
tail -f kxinstall/delta-data/DeltaControlData/logdir/refdata_tp_reference_a.*.log
```

The same content appears in the DC UI's View Log viewer - both read from the same file on disk. Reading from the cli should be the preferred approach as it is easier to manipulate and view larger log files. Viewing large portions of the log file at once should be generally avoided as it requires a very large memory overhead in Delta Control process.
