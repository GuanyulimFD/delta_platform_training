# Lesson 2.3 - Navigation Tree

_Module 2: Delta Control · ~TBD min_

## Introduction

This lesson defines what the Navigation Tree is and how to use it.

## Key Concepts

The tree on the left is how you find and browse everything in your system. It supports two ways of looking at your entities, either by Package or by Entity type.

- **Package view** - when Control is deployed, it is done so with a group of Packages which contain the entities that you see in the UI. The packages are expandable in the Navigation Tree to be able to see all of the entities that are under it. When the application is first deployed, every entity will be under a Package. However, when you create a new entity, such as a User or a Dashboard, you do not necessarily need to add this new entity to a package (although it is highly recommended to do so). If you do not add the new entity to a package, it will be auto assigned to the 'Unpackaged Entities' dropdown at the top of the Navigation Tree.
  - As well as being able to create new entities, we can also create new packages. These are useful if we are going to be creating a lot of new entities, and we want somewhere to store all of our new analytics and config parameters etc.
- **Entity view** - the other way to view the Navigation Tree is by Entity. This is where the package names are done away with, and entities are grouped together based on the type of entity it is. This can be very useful if you are looking for a particular analytic or schema, but you can't remember the name of it or what package it comes in. When you toggle to Entity view, you can see all of the different types of entities that are currently in use in the application.

The main entities that you will use are mentioned below, with more detail on the other ones found in the KX official documentation.

| Entity Type | Use |
|---|---|
| Analytics | Reusable analytic functions and groups available to any instance/template. |
| Dashboards | A list of all of the available dashboards that can be accessed from the home page. |
| Instances | The list of processes that are available to run in the application. |
| Parameters | The configuration files used by the instances. |
| Schemas | Define the structure of the data tables. |
| Service Classes | A scalable version of a standard instance. Useful if you need to bring them up and down regularly. |
| Tasks | These are usually sub-instances of the Process Instances, generally you would have 2-3 tasks per instance. Allows for load sharing. |
| Workflows | Defines the startup order of a list of instances or tasks. |
