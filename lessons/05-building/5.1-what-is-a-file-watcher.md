# Lesson 5.1 - What Is a File Watcher?

_Module 5: Building the File Watcher Data Loader. ~10 min_

## Introduction

This lesson introduces the concept of the File Watcher in Delta Platform

## Key Concepts

The file watcher is a component in Delta Control used for loading batch data from static files. This is an alternative to tick data to try and get data into the system. A vendor drops an end-of-day CSV export onto a shared drive, another system writes a JSON extract once an hour, an overnight process produces a fixed-width report. Someone (or something) has to notice when those files land, and turn them into data the platform can actually use.
That "someone" is the **File Watcher** (often shortened to *FW*).

A File Watcher is a KX Delta Platform process, built from the DS_FILEWATCHER template, whose only job is to:

1. **Poll** a configured list of directories on a regular interval, looking for new files.
2. **Match** any file it finds against a set of expected filename patterns (regular expressions).
3. **React** to a match — publish a message announcing the file's arrival and, if configured, call a specific piece of logic (an **analytic**) to actually read the file, transform the data, and load or publish it into the platform.

It can also do the reverse: if a file that was *expected* by a certain time never shows up, the File Watcher can raise an **alert**, which is often just as important as processing the files that do arrive. The DS_FILEWATCHER template is explained in more detail in Lesson 5.4

### Why not just write a script?

You certainly could write a standalone script to watch a folder. The value of doing it through the File Watcher template instead is that it plugs into everything else KX Control already gives you for free: managed configuration, restart-on-failure, logging, monitoring, and the same version-controlled, entitlement-secured development environment as the rest of your system. You describe *what* to watch for and *what* to do about it — the platform handles the rest.
