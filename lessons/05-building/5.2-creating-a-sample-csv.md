## Key Concepts

We're going to build a small, complete example: a directory that gets watched for a `sampleOrders_<date>.csv` file, a loader analytic that reads it into a table, and a File Watcher process that ties it all together.

The first step is to generate the sample CSV that we will be loading in. There are a couple of ways to do this, but we will build our own CSV on the server and save it in a location that is not being watched by the file watcher.

Let's create a simple "orders" file to load. Each row represents a single order: a timestamp, a symbol (instrument), a quantity, and a price. Create a file named sampleOrders_20260101.csv using a text editor and insert the below contents into the file:

```
time,sym,qty,price
2026-01-01T09:30:00.000,AAPL,100,182.35
2026-01-01T09:31:12.500,MSFT,50,412.10
2026-01-01T09:32:45.250,GOOG,25,168.90
2026-01-01T09:34:03.100,AAPL,75,182.50
2026-01-01T09:36:22.750,AMZN,10,201.75
```

You can change these values to be anything that you might want, but the number of values per row must be consistent. Notice the filename follows a pattern: `<tableName>_<date>.csv`. This isn't a strict platform requirement, but it's a common and useful convention — it lets one loader analytic extract the date straight from the filename (handy for partitioning data later), and it lets your matching pattern stay generic instead of hard-coding a single day's file.

Now that we have the sample CSV created, we can save that for use later whilst we build the other necessary components.

### Common File Formats

CSV files are one example of file formats that would need to be ingested into a system. There are other formats, but thankfully these are well documented and for some, there are helpful namespaces to help with the ingestion.

- Fixed-width text files: some files will not separate their values by a comma or a pipe (|), but each column will have a consistent width for each row. This is common for date and time types, where there is no punctuation but all of the values are there. An example of this can be seen here (link not captured from source — canvas-rendered page, no extractable URL).
- JSON files can be read in using the .j namespace, and there are APIs built to help with the serializing and deserializing of this data here (link not captured from source).
- Files can also be in raw binary formats, which can be read in with the 'read1' operator.
