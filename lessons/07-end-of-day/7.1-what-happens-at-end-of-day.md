# Lesson 7.1 - What Happens at End-of-Day

_Module 7: End-of-Day Processing and Persistence. ~8 min_

## Introduction

This lesson explains what end-of-day (EOD) does and the order in which it runs across the TP, RDB and HDB.

## Key Concepts

The RDB holds the current day's data in memory, and the HDB holds earlier days on disk (Lesson 8.1). EOD runs once a day and moves the day's data from the RDB to the HDB.

### The end-of-day sequence

1. At `eodTime`, `refdata_tp_reference_a` rolls its tickerplant log to a new file for the next day and sends the EOD signal to every process subscribed to it.
2. Each subscribed process runs the analytic set in its `eodFunct` instance parameter for the date that has ended. On `refdata_rdb_reference_a` this is `dxEODSaveAndDelete`. Other process types, such as RTEs, have their own `eodFunct`.
3. The RDB saves each table in its EOD table list to the HDB directory as a date partition, then empties the table.
4. `refdata_hdb_reference_a` reloads, and the new date can be queried.

Lesson 7.2 covers the EOD function in detail.

### How tables are stored on disk

The default EOD function saves every table as a **partitioned table**. For each table it calls:

```q
.Q.dpft[`:.;dt;`sym;t]
```

This writes the table into a directory named after the date (`dt`) under the HDB root and enumerates its symbol columns against the shared `sym` file. It also sorts the table by `sym` and gives `sym` the parted attribute, so queries filtered on `sym` within a date are fast. Each table in the partition is splayed, with one file per column:

```
hdblog/
├── sym
└── 2026.11.24/
    ├── sampleOrders/
    │   ├── .d
    │   ├── time
    │   ├── sym
    │   ├── qty
    │   └── price
    └── sampleReferenceData/
        ├── .d
        ├── time
        ├── sym
        ├── industry
        └── region
```

`date` isn't stored in the table. It comes from the partition directory name, and is available as a virtual column when the HDB is queried.

kdb+ can also store tables flat, splayed without partitions, or segmented across disks. This course uses the default partitioned layout throughout. The other forms are described at https://code.kx.com/kdb-x/how_to/interact_with_databases/overview.html, and `.Q.dpft` at https://code.kx.com/q/ref/dotq/#dpft-save-table.

### Delta Platform vs vanilla kdb+

In a vanilla kdb+ tick setup, the EOD save is written by hand in the RDB script (`.u.end`, https://code.kx.com/q/architecture/rq/). In Delta Platform, the same steps are set through instance parameters (`eodTime`, `eodFunct`, `tableEodList`, `hdbProcess`, `directory`), covered in Lesson 7.3.
