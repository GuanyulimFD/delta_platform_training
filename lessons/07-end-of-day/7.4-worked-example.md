# Lesson 7.4 - Worked Example: Running EOD and Validating the HDB

_Module 7: End-of-Day Processing and Persistence. ~12 min_

## Introduction

This lesson triggers end-of-day, then checks that both the orders and the reference data were correctly saved to the HDB.

## Key Concepts

Waiting until midnight to see EOD happen isn't practical, so we'll temporarily move the TP's `eodTime` to a few minutes from now.

1. **Make sure there's data to save.** Complete Lesson 6.9 first, so the RDB holds the 5 published orders and 4 reference rows. Connect to `refdata_rdb_reference_a` and note the counts:

   ```q
   count each `sampleOrders`sampleReferenceData!(sampleOrders;sampleReferenceData)
   ```

2. **Move EOD closer.** Open `refdata_tp_reference_a`, go to Instance Params and set `eodTime` to a few minutes ahead of the current time (in **GMT**, because `timeType` is `gmt`, Lesson 7.3). Click Save.
3. **Restart the TP** so the new `eodTime` is picked up (Lesson 6.2). Because it is restarted on the same day, the TP keeps today's log, and the RDB's data is unaffected.
4. **Watch the RDB log.** Open the RDB's log in the log viewer (Lesson 4.5). When `eodTime` passes, you should see the lines from `dxEODSaveAndDelete` (Lesson 7.2):
   - `EOD function start`
   - `Performing EOD for sampleOrders, date …`, then `Resetting table: sampleOrders` and `Finished EOD for sampleOrders, date …`, with the larger table processed first
   - the same three lines for `sampleReferenceData`
5. **Check the RDB is empty.** Both tables have been reset:

   ```q
   count sampleOrders            / 0
   count sampleReferenceData     / 0
   ```

6. **Check the HDB.** Connect to `refdata_hdb_reference_a`:

   ```q
   tables[]                                          / includes sampleOrders and sampleReferenceData
   select count i by date from sampleOrders          / 2026.01.01 (Module 5 batch load) plus today's EOD partition
   meta sampleOrders                                 / sym has the parted (p) attribute
   select from sampleReferenceData where date=last date   / the 4 reference rows, in the newest partition
   ```

   Notice that the published rows have `time` values on 2026-01-02 but are stored in the newest partition (`last date`), which is the EOD date. The partition comes from the date the EOD function was given, not from the data.

   > **Note:** the 2026.01.01 partition written by Lesson 5.6 contains only `sampleOrders`. kdb+ expects every partitioned table to exist in every partition, so filter `sampleReferenceData` queries by date as above, or fill in the missing table with `.Q.chk` (https://code.kx.com/q/ref/dotq/#chk-fill-hdb).

7. **Spot the missing reference data.** Join the orders to their reference data:

   ```q
   o:select from sampleOrders where date=last date;
   r:select sym,industry,region from sampleReferenceData where date=last date;
   o lj `sym xkey r
   ```

   The AMZN order has empty `industry` and `region`, because the reference file in Lesson 6.5 had no AMZN row. Gaps like this are worth checking for after every EOD.

8. **Check the files on disk.** List the HDB directory, `ENV=DELTADATA_HOME=/DaaSData/hdblog`. You should see the `sym` file and one directory per date, each holding a `sampleOrders` directory (and, for today, `sampleReferenceData`) with one file per column.

   > **Note:** screenshot to be captured: directory listing of the HDB showing the date partitions.

9. **Put eodTime back.** Set `eodTime` on `refdata_tp_reference_a` back to `00:00`, save, and restart the TP.

### Troubleshooting

- **Nothing is saved:** the table isn't listed in `DS_TABLES_EOD_LIST:refdata_rdbEodConfig`, or the RDB's `tableEodList` still points at DEFAULT (Lesson 7.3).
- **Data is saved but the HDB doesn't show it:** the RDB saved somewhere other than where the HDB loads from. Check the HDB's `directory`. Also check the HDB reloaded: `dxEODSaveAndDelete` skips the reload if no HDB has a port registered.
- **"Error writing table to HDB Dir" in the RDB log:** the error message includes the HDB directory, date and table. A common cause is a table without a `sym` column, which `.Q.dpft` requires.
- **EOD never fires:** check that `eodTime` was saved, the TP was restarted, and the time was set in GMT (`timeType` is `gmt`).
